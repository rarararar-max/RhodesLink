一、这是什么软件
============================================================

罗德岛通讯端是一款以 AI 角色互动为核心的聊天软件。你可以创建自己的角色，
为角色填写性格和背景，与角色进行长期聊天，也可以创建群聊、制作互动剧情，
给角色关联世界观资料，并在换设备时迁移角色和聊天数据。

它主要适合以下玩法：

1. 角色陪伴：创建一个有固定性格和说话方式的角色，进行日常对话。
2. 剧情互动：使用线上、线下、导演模式，进行轻小说式或沉浸式对话。
3. 群像故事：把多个角色放进群聊，观察他们之间的关系和互动。
4. 长期养成：让角色通过聊天记住你的偏好、约定和共同经历。
5. 世界观创作：使用知识库和 Galgame 功能制作自己的角色故事。
6. 角色分享：将角色设定单独导出，分享给朋友或迁移到另一份数据中。

重要说明：AI 的回复来自你配置的模型服务。不同模型的表达能力、速度、稳定性
和收费方式可能不同。软件负责保存角色、聊天和相关设置，但不会保证每次回复都
完全符合你的预期。

============================================================
二、第一次使用
============================================================

建议按照下面的顺序完成设置。

第一步：填写你的身份

进入“我”或“身份设置”，填写昵称、性别、个人简介并设置头像。
你的身份资料会帮助角色理解应该如何称呼你，以及你希望以什么身份参与互动。

个人简介可以写：

• 你希望角色如何称呼你
• 你的职业、兴趣或背景
• 你和角色的关系
• 你希望角色知道的基本信息

昵称不能为空。修改资料后请点击“保存”。

第二步：配置聊天模型

进入“我 → 模型设置”，填写模型厂商、模型名称、接口地址和 API Key，然后使用
“测试聊天模型”确认连接正常。

如果你不知道如何选择模型，可以先使用服务商推荐的通用聊天模型。模型配置不是
角色设定；模型决定“由谁来生成文字”，角色人设决定“角色应该怎样说话”。

第三步：创建或导入角色

你可以新建角色，也可以通过“角色设定分享”导入角色卡。新建角色后，建议至少
填写角色名称、身份简介、性格、说话方式以及与你的关系。

第四步：开始聊天

进入角色的私聊页面，在输入框中发送第一条消息。建议第一句话直接告诉角色你
想进行什么样的互动，例如：

“我们从朋友关系开始，进行日常聊天。”
“请用轻松的语气和我讨论今天发生的事情。”
“我们开始一段悬疑剧情，但不要替我决定行动。”

第五步：按需开启记忆和知识库

普通聊天不需要先开启所有高级功能。建议先熟悉私聊和群聊，再根据需要开启记忆、
向量记忆或知识库。

============================================================
三、模型设置
============================================================

模型设置位于“我 → 模型设置”。不同功能使用的模型可能不同，可以分别配置。

1. 聊天模型

用于生成角色回复、群聊消息、动态、日记以及部分 AI 辅助内容。

需要填写：

• 服务商
• 模型名称
• API 地址（使用自定义服务商时）
• API Key

保存前可以使用测试功能。API Key 是服务商发放的访问凭证，不要把它发给别人，
也不要把包含 Key 的截图上传到公开平台。

2. 识图模型

用于理解你发送的图片。如果没有配置识图模型，文字聊天仍然可以使用，但图片
聊天无法正常识别。

通常需要填写识图地址、模型名和密钥。部分配置允许复用聊天模型的 API Key。

3. 向量模型

用于帮助角色从较早的记忆或知识库资料中找回“意思相近”的内容。它不是聊天模型，
也不会直接生成回复。详细说明见第八章。

4. 语音识别 ASR

用于把你说的话转换成文字。首次使用时需要配置语音识别服务并授权麦克风权限。
识别结果会回填到输入框，确认无误后再发送。

5. 文字转语音 TTS

用于朗读角色回复。除了配置 TTS 模型，还要在角色编辑页面为角色配置音色。
如果角色没有音色，聊天消息不会显示正常的播放效果。

============================================================
四、你的身份与角色人设
============================================================

4.1 你的身份

“身份设置”是你自己的资料，包括昵称、头像、性别和简介。它回答的是：

“你是谁？角色应该如何理解你？”

建议填写真实使用场景中稳定的信息，不要把一次性的临时情绪全部写进个人简介。

4.2 角色人设

角色人设是角色的基础说明，回答的是：

“这个角色是谁？她或他应该怎样和我交流？”

建议填写以下内容：

• 身份：角色是谁、从事什么工作、处于什么环境
• 性格：外向、谨慎、毒舌、温柔、认真等
• 背景：角色经历过什么，熟悉哪些事情
• 目标：角色当前想完成什么
• 说话方式：句子长短、语气、称呼、口头禅
• 关系：角色与你是什么关系
• 禁区：哪些内容不要出现，哪些行为不符合角色

人设示例：

“你是一个谨慎但愿意照顾人的情报分析员。你说话简洁，习惯先观察再下结论。
你称呼用户为‘博士’，不替用户决定行动。遇到未知信息时要承认不知道，不能
凭空编造结果。”

4.3 私聊人设与群聊人设

私聊人设和群聊人设是两套独立设定。你可以让角色在私聊中更加亲密，在群聊中
更加克制；也可以让角色在群聊中更活跃，在私聊中更安静。

软件提供 1、2、3 号人设槽位。每个槽位独立保存，切换槽位不会自动合并内容。
如果你修改了人设，记得点击角色编辑页面的“保存”。

4.4 AI 人设助手

角色编辑页面中的 AI 人设助手可以根据你的描述生成一份角色资料。生成后请检查
姓名、背景、说话方式和禁区，满意后点击“使用这份人设”，最后仍需在角色编辑页
点击“保存”。只生成预览而没有保存，退出页面后不会成为永久设定。

4.5 关系设置

你可以设置角色与你的关系，也可以设置角色和其他角色之间的关系。角色关系可以
影响称呼、群聊互动和公开近况传递。关系默认是单向的：A 把 B 当朋友，不代表 B
也把 A 当朋友。

关系传递的主要是公开信息，不等于角色之间共享全部私聊内容。

============================================================
五、私聊
============================================================

5.1 发送消息

进入角色后，在底部“消息...”输入框中输入内容，点击“发送”。文字、图片和语音
是不同的输入方式；语音识别完成后会先回填文字，不会未经确认直接发送。

如果你连续快速发送多条文字，软件可能把相邻的内容合并成同一轮表达，以便角色
综合理解。建议等待角色回复后再继续发送重要剧情内容。

5.2 三种互动模式

点击输入栏附近的模式按钮，可以切换：

线上：适合模拟即时通讯，例如短信、通讯软件和网络聊天。通常以角色台词为主。

线下：适合面对面场景。角色可以结合场景、动作和表情进行互动，适合沉浸式剧情。

导演：适合你直接描述场景和事件。你可以像写剧本一样说“房间里的灯突然熄灭”，
让 AI 根据你的描述继续安排剧情，但仍建议明确哪些行动由你决定。

模式切换会影响后续回复的表达方式。切换后第一轮回复可能会特别解释当前场景，
这是正常现象。

5.3 图片聊天

通过相册或拍照添加图片，并可以附带文字说明。使用前需要配置识图模型。识图失败
时，图片通常会保留在消息中，可以检查识图配置后点击失败消息重试。

5.4 语音输入

需要配置 ASR 服务并允许麦克风权限。点击录音开始说话，点击停止后等待文字识别。
识别结果会出现在输入框中，请先检查文字，再点击发送。

5.5 消息操作

长按消息可以打开操作菜单：

• 复制：复制消息文字
• 撤回：撤回用户消息，或撤回 AI 回复中的某个片段
• 重说：让角色替换刚才的回复，适合对结果不满意时使用
• 继续说：让角色承接上一条回复继续说，不重新开场，也不主动换话题
• 播放：使用 TTS 朗读角色回复
• 重试：重新发送未送达的消息

重说会替换原来的 AI 回复，不会额外增加一条独立回复。继续说会新增一条回复。
撤回会影响后续记忆和摘要，不能只理解为“把气泡从屏幕上隐藏”。

5.6 剧情存档

进入顶部菜单中的“剧情存档”可以保存当前剧情进度。完成至少一轮有效聊天后，
通常才适合创建存档。读取存档不会删除当前聊天记录，但存档之后产生的内容不会
继续影响读取后的剧情。

5.7 重新开始会话

“重新开始会话”适合开启新的篇章。旧消息会保留为历史，但后续回复默认只参考新
篇章内容。它不是立即删除聊天。如果你要彻底删除数据，应使用数据管理或对应的
删除功能，并在操作前确认风险。

============================================================
六、群聊
============================================================

6.1 创建群聊

创建群聊时需要填写群名称并选择成员。进入“群聊编辑”后，可以设置群头像、群聊
行为规则和成员是否允许发言。

群聊行为规则示例：

“这是一个轻松的任务讨论群。成员之间可以互相吐槽，但讨论任务时要保持重点。
每次只推进一个小事件，不要替用户决定行动。”

6.2 成员发言权限

你可以把某个成员设置为“不允许发言”。这适合让某个角色只作为背景成员，或暂时
控制群聊节奏。

6.3 空闲自动聊天

打开“空闲自动聊天”后，群聊可以在你没有输入时，按照随机时间间隔自行互动。
如果不希望群聊自动产生内容，可以关闭此功能，或在权限管理中调整相关权限。

6.4 群聊中的常用操作

群聊支持发送文字、图片、语音和礼物，也可以查看聊天记录、编辑群聊、更换背景图。
部分私聊专属功能，例如“重说”和“继续说”，不一定出现在群聊消息菜单中。

6.5 重新开始群聊

重新开始群聊会建立一个新的上下文边界。旧群聊不会删除，会以浅灰色历史显示；
之后的回复默认只参考新群聊内容。

6.6 解散群聊

“解散群聊”是永久删除操作，群聊删除后无法恢复。只是想开启新剧情时，请使用
“重新开始群聊”，不要使用“解散群聊”。

七、记忆功能
============================================================

7.1 记忆能解决什么问题

普通聊天窗口不可能永远把全部历史原文都交给 AI。记忆功能会把聊天中比较重要的
事实、偏好、约定和经历整理出来，在以后相关话题出现时提供给角色参考。

例如你曾经说过“我不喜欢太甜的饮料”，未来当你问角色推荐饮品时，角色有机会
参考这条信息，而不是每次都从零开始猜。

记忆不是完美的录像。AI 可能漏记、误解或把不重要的内容记下来，重要信息建议
手动管理和检查。

7.2 三层记忆

L1 近期记录：刚从聊天中提取出来的具体事实，例如“用户今天想吃拉面”。

L2 长期记忆：多条相关近期记录合并后的稳定结论，例如“用户喜欢日式料理”。

L3 角色记得的你：更长期、更稳定的认识，例如“用户长期偏好清淡、热食”。

这三层的目的，是把零散聊天逐渐整理成更稳定的角色认知。并非所有内容都会自动
升级，也不是达到数量后一定成功合并。

7.3 记忆生成和记忆注入

记忆生成：决定以后是否继续从聊天、群聊、动态、评论和日记中提取新记忆。

记忆注入：决定当前对话是否允许读取已有记忆。

两者不同。关闭记忆生成不会删除已有记忆；关闭某个记忆来源的注入，也不会删除
这类记忆，只是不在当前场景提供给 AI。

7.4 记忆更新频率

设置中的“每多少条消息提取一次”控制记忆整理频率。数值较小，记忆更新更及时，
但可能增加模型请求；数值较大，调用更少，但新事情可能要过一会儿才进入记忆。

7.5 记忆管理

可以从“设置 → 记忆 → 管理”进入记忆管理，也可以从角色编辑进入角色记忆。
支持搜索、按角色筛选、按来源筛选、按记忆层级筛选、新增手动记忆和删除记忆。

建议手动添加适合长期保留的内容，例如：

“用户不喜欢被公开称呼真实姓名。”
“用户和该角色约定，遇到不确定的事情要先询问。”

不建议把短期、容易变化的内容写成长期记忆。

7.6 记忆隐私

私聊记忆默认不会直接传给其他角色。关系网主要传递公开信息，不等于角色之间
共享你的私聊隐私。使用群聊、动态和关系传递时，请注意哪些内容适合公开。

============================================================
八、向量记忆：帮助角色找回久远经历
============================================================

8.1 不懂技术也可以这样理解

向量记忆就是一种“按意思找记忆”的方式。

传统关键词搜索可能要求问题中出现和原文一样的词。例如记忆里写“喜欢热汤面”，
你问“冷天想吃什么”，两句话没有完全相同的关键词，普通搜索可能找不到。

向量记忆会把文字转换成一种用于比较含义的数字表示，再寻找意思接近的记忆。它
因此有机会理解“热汤面”和“冷天适合的食物”之间的关联。

你不需要自己查看这些数字，也不需要手动操作。软件会在需要时自动查找相关记忆。

8.2 手机自带的免费版

本地模式会在手机上建立检索索引，不上传聊天内容，也不产生额外的 Embedding API
费用。它适合注重隐私、希望零额外服务费用，或只是想先试用记忆检索的用户。

它对近义表达和复杂语义的理解能力相对有限。如果角色偶尔找不到很早的相关经历，
不一定是聊天记录丢失，也可能是本地检索没有判断出两句话有关。

8.3 付费 Embedding 模式

第三方模式通常有更好的语义匹配能力，但建立和查询记忆时，会把相关记忆文本发
给你配置的第三方服务，并可能产生服务商费用。使用前请确认服务商的隐私政策、
计费方式和数据处理范围。

8.4 什么时候需要更换模式

建议先使用手机自带的免费版。只有当你经常遇到“明明记过却找不到”，并且愿意接受
第三方服务和可能的费用时，再考虑付费模式。

8.5 更换向量模型后为什么要重建

不同检索方式生成的索引不一定兼容。更换本地/第三方模式、服务商、接口地址或
模型名称后，软件可能清理旧索引并要求重新建立。

重建不会删除原始记忆，但会重新为记忆建立检索数据。第三方模式下，记忆数量较多
时可能产生较多请求和费用，请确认后再开始。

============================================================
九、知识库：给角色增加资料
============================================================

9.1 知识库适合放什么

知识库适合放相对稳定、希望角色长期参考的资料，例如：

• 世界观和阵营设定
• 角色的详细背景资料
• 小说、剧本或 Galgame 设定
• 产品说明、课程资料或工作文档
• 地点、组织、历史事件说明

记忆更像“聊天后自动记住的经历”，知识库更像“你主动交给角色阅读的资料”。

9.2 新建或导入知识库

进入“我 → 知识库”，可以新建知识库，也可以导入 TXT 或 MD 文件。导入后软件会
自动整理内容并分成多个片段，随后建立检索索引。

限制：

• 只支持 TXT 或 MD
• 单个文件不超过 2 MB
• 正文不超过 20 万字符
• 最多 500 个分段

文件过大时，建议拆成多本知识库，例如分别建立“世界观”“角色关系”“章节资料”。

9.3 关联角色和场景

进入知识库详情，点击“关联角色”，勾选需要使用资料的角色。随后打开适用场景，
选择私聊、群聊、动态、评论或日记。

资料要参与生成，通常需要同时满足下面条件：

1. 角色已经关联该知识库。
2. 当前使用场景已经开启。

3. 索引可用且与当前向量模型匹配。“索引完成”可以完整使用；“部分失败”时，已成功建立索引的分段仍可使用，可在详情页只重试失败分段。

知识库也会根据当前话题选择相关片段，不是每次把整本资料全部塞给 AI。

私聊时，每本符合条件的知识库最多先召回 3 个相关片段，再从全部候选中按相关度选择最多 3 段。最终不保证每本资料各占一段；同一本资料最相关时，可以同时提供多段。群聊会对重复关联的同一本知识库去重，最多引用 2 段。动态、评论和日记只引用 1 段最相关资料；检索慢或不可用时，内容仍会照常生成。

9.4 分段管理

进入“分段管理”可以查看软件自动整理出的片段。你可以编辑来源标题、正文和关键词，
也可以新增、删除、启用或停用片段。

停用一个片段，表示保留它但暂时不让它参与检索；删除片段则会让它不再参与检索。
修改或启用状态后需要重新索引。

如果修改知识库原文并重新分段，手动新增、编辑、启用、停用和删除的分段设置可能
会被新的自动分段覆盖。

9.5 本地索引和远程索引

使用手机本地模式时，知识库索引在本机建立。使用第三方向量服务时，索引前会显示
预计请求次数，并要求你确认，因为可能产生费用，资料片段也可能发送到该服务商。
聊天检索时，当前问题文本也会发送到所配置的向量服务。远程索引会限制单个分段等待时间，并只对临时网络、限流或服务端错误进行有限重试。

============================================================
十、聊天表现与长度设置
============================================================

10.1 什么是上下文

上下文可以理解为“AI 本轮回复前能看到的资料总量”。它包括角色人设、系统规则、
相关记忆、知识库片段、最近聊天和你当前发送的内容。

它不是简单的聊天条数。即使只保留几条消息，如果人设、知识库或记忆很长，也可能
占用较多上下文空间。

10.2 历史消息数量

历史消息数量决定本轮优先回看多少条最近聊天。增加数量通常能保持更连续的对话，
但会增加请求内容、等待时间和可能的费用。

10.3 最大上下文长度

最大上下文长度决定本轮最多允许发送多少文字给模型。设置太小，角色较容易忽略
早期聊天；设置太大，速度和费用可能上升，而且还要受模型服务商本身的上限影响。

当内容超出上限时，软件会优先减少较早的原始聊天。已经整理成记忆的内容不一定
会消失，但如果人设和知识库本身过长，也会占用空间。

10.4 回复长度

在“聊天表现”中可以设置：

• 台词最少和最多字数
• 旁白最少和最多字数
• 台词段数
• 旁白段数
• 群聊每条消息的字数
• 群聊成员发言次数

这些设置是对 AI 的写作要求，不是绝对保证。如果模型或接口本身有输出上限，实际
回复仍可能更短；设置过大也可能让回复拖沓。

建议：日常聊天使用较短回复，剧情模式适当增加旁白和段数；群聊不要同时设置过多
成员和过长消息，否则等待时间会明显增加。

10.5 创意程度

创意程度较低时，回复更稳定、保守，但可能重复；创意程度较高时，内容更发散，
但也更容易跑题或前后不一致。角色日常聊天通常使用中等数值，剧情创作可以适度
提高。发现角色跑偏时，先降低创意程度并检查人设规则。

10.6 推荐预设

聊天设置中的推荐预设通常包括“省钱”“标准”“完整”。它们会组合调整历史回看、
记忆提取频率、自动内容和主动联系密度。

• 省钱：减少额外生成和参考内容，适合低成本使用
• 标准：速度、效果和成本之间平衡，适合大多数用户
• 完整：保留更多内容并增加自动能力，可能需要更多请求

============================================================
十一、角色说话规则
============================================================

“角色说话规则”适合有一定经验的用户使用。它可以控制私聊、群聊、动态、评论、
日记和派遣等场景的表达方式。

适合修改：

• 角色口吻和语气
• 回复是否简短
• 世界观中的行为规则
• 群聊氛围
• 剧情推进方式
• 哪些内容应当避免

不建议随意删除系统提供的关键变量。变量是软件把角色名、用户资料、记忆、当前
消息等内容放进提示中的位置。如果删除了角色人设或当前消息相关变量，AI 可能
收不到重要资料。

如果不清楚变量的作用，建议只在原有规则末尾增加自己的要求，不要重写整份模板。
发现角色行为异常时，可以使用恢复默认功能，再逐步添加自己的规则。

十二、Galgame
============================================================

12.1 功能定位

Galgame 是一个从“设定”到“试玩”的互动剧情工具。玩家负责决定行动，AI 负责在
角色设定和章节规则范围内生成旁白、台词和剧情变化。

12.2 创作流程

进入“功能 → Galgame”，按照以下顺序操作：

1. 创建项目并填写游戏名称、简介、创作风格和创作禁区。
2. 创建角色，填写性格、背景、目标、说话方式、关系、秘密和禁区。
3. 上传透明 PNG 立绘。
4. 上传场景背景。
5. 添加章节，填写章节内容、开场描述、目标、氛围和注意事项。
6. 设置允许出场角色和允许使用的背景。
7. 点击“项目检查”。
8. 检查通过后点击“进入游戏试玩”。

12.3 试玩玩法

试玩中可以点击预设选项，也可以在“自由输入”中描述自己的行动，例如：

“我没有回答，先观察桌上的信封。”
“我走到窗边，看看外面有没有人。”

选项通常只描述行动，不应该直接写出结果或剧透。AI 会根据当前章节和角色规则
推进一小步剧情。

12.4 项目检查

项目检查会检查游戏名称、剧情描述、角色、立绘、章节、玩家角色以及资源引用。
如果提示缺少内容，先补齐再试玩，避免剧情中出现空角色、空背景或无法显示的立绘。

12.5 草稿、存档和分享

Galgame 项目支持本地草稿、自动保存、试玩进度存档、读档、重新开始和分享。建议
每完成一个章节就保存一次项目，重要版本可以另行导出或复制保存。

十三、角色卡与聊天记录导出
============================================================

13.1 导出角色设定

进入“我 → 数据管理 → 备份与恢复 → 角色设定分享 → 导出角色设定”，选择角色并
保存 .roperator 文件。

角色卡主要包含：

• 角色资料
• 头像（应用内部保存的图片）
• 私聊人设 1、2、3 号槽位
• 群聊人设 1、2、3 号槽位
• 角色关系

角色卡不包含：

• 私聊和群聊记录
• 记忆
• 日记、动态、评论
• 聊天背景
• 权限开关和角色音量

13.2 导入角色设定

选择 .roperator 文件并查看预览后，可以选择“创建副本”或“覆盖现有角色”。

创建副本：保留原角色，并新建一个导入角色。

覆盖现有角色：替换目标角色的人设、状态、关系、语音和角色数值，但不会修改目标
角色已有的聊天和共同经历。

角色关系通过角色 ID 匹配。如果接收方没有对应角色，相关关系可能被跳过。

13.3 导出聊天记录

进入“我 → 数据管理 → 备份与恢复 → 保存聊天记录”，选择私聊或群聊，再选择
Markdown 或纯文本格式。

聊天记录导出文件适合阅读、分享和整理故事，不能用于恢复应用数据。

十四、完整备份与恢复
============================================================

14.1 创建完整备份

进入“我 → 数据管理 → 备份与恢复 → 完整备份”，选择：

• 包含本机已保存图片：适合换手机或完整迁移
• 仅文字和资料：文件更小，不包含本机图片

完整备份可以包含角色、关系、聊天、记忆、日记、动态、评论、知识库、设置、剧情
存档和应用内部图片等资料。

完整备份不会包含账号密码、API Key 或模型密钥。

14.2 恢复完整备份

点击“选择完整备份文件”，选择 .rbackup 文件后查看备份清单。确认恢复后，当前
数据会被清空并替换为备份内容。

每次恢复前软件会自动创建当前数据的安全备份，最多保留最近 5 份。恢复完成后，
请重新进入“模型设置”填写聊天、识图、向量、语音识别和文字转语音服务。

14.3 换手机建议

旧手机：

1. 完成一次完整备份，并选择是否包含图片。
2. 将 .rbackup 文件保存到可靠位置。
3. 确认文件没有被聊天软件压缩或损坏。

新手机：

1. 安装罗德岛通讯端。
2. 导入完整备份。
3. 检查角色、聊天和知识库。
4. 重新配置模型服务和 API Key。
5. 如有需要，重建记忆和知识库索引。

完整备份文件本质上是数据文件，不等于密码保险箱。请妥善保管，不要随便发给他人。

============================================================
十五、数据管理与隐私
============================================================

15.1 自动清理

进入“我 → 数据管理”，可以为记忆锚点、聊天记录、日记、动态和派遣历史设置保留
期限。可选 3 天、7 天、14 天、30 天、90 天或“永不”。

“立即清理所有过期数据”会删除超过期限的数据，且不能恢复。执行前建议先创建完整
备份。自动清理规则与“重新开始会话”不同：重新开始只是建立新的剧情边界，自动
清理才会按期限删除数据。

15.2 本地和远程

角色、聊天、记忆和知识库会保存在设备的数据中，但只要你配置了第三方 AI 服务，
发送给 AI 的内容就可能经过该服务商的服务器。图片识别、语音识别、文字转语音和
付费向量检索也可能分别发送内容。

使用第三方服务前，请阅读服务商的隐私政策和计费规则，不要把不适合外传的隐私资料
放进会发送到第三方的聊天或知识库。

15.3 调试日志

开启调试日志后，可以查看模型请求、返回和错误详情。这有助于排查问题，但日志
可能包含聊天上下文和用户输入。排查完成后建议关闭，尤其不要把未经检查的日志
文件发到公开平台。

15.4 备份安全

完整备份不保存 API Key 和模型密钥，但会保存大量角色、聊天和记忆资料。角色卡也
可能包含完整人设和头像。无论是哪种导出文件，都建议像保存私人资料一样妥善管理。

十六、常见问题
============================================================

问：角色为什么不记得我以前说过的话？

答：先检查记忆生成和记忆注入是否开启，再检查向量索引状态、记忆来源和当前话题
是否相关。记忆不是完整录像，AI 也可能没有提取到这条内容。重要信息可以手动添加
为记忆。

问：关闭记忆会删除以前的记忆吗？

答：不会。关闭记忆生成只是停止产生新的记忆；关闭记忆注入只是当前不读取已有
记忆。要删除已有内容，请进入记忆管理手动删除。

问：向量记忆是不是必须开启？

答：不是。不开启也可以正常聊天。向量记忆主要帮助角色从更早的内容中寻找意思
相关的经历，适合长期聊天或资料较多的用户。

问：为什么知识库导入了，但角色没有使用？

答：检查三点：知识库是否已经索引完成；当前角色是否已关联；当前场景是否开启。
另外，知识库会根据话题选择相关片段，问题和资料关系太远时也可能不会引用。

问：修改知识库后为什么要重新索引？

答：索引是资料的“可查找目录”。正文或分段变了，旧目录就可能不准确，因此需要
重新建立。第三方模式下重建可能产生服务请求和费用。

问：角色回复太短怎么办？

答：进入聊天表现，增加台词最少字数、旁白最少字数或段数，并检查模型本身的输出
限制。字数设置只是写作要求，不是绝对保证。

问：角色回复太长怎么办？

答：降低台词和旁白最大字数、减少段数，或使用“省钱”或“标准”预设。也可以在
角色说话规则中写明“优先简短回答”。

问：角色忘记了很早的聊天，但记忆里明明有相关内容怎么办？

答：检查记忆注入来源和向量索引状态，并尝试在记忆管理中搜索这条记忆。更换向量
模型后需要重建索引。适当提高检索模式或候选范围也可能改善找回效果。

问：为什么不能发送图片？

答：需要在模型设置中配置识图地址、模型名和密钥。部分服务允许复用聊天 API Key，
但识图服务仍需正确配置。

问：为什么不能播放语音？

答：需要配置 TTS 模型，并在角色编辑中配置角色音色。群聊中还需要为对应发送者
配置音色。

问：AI 回复失败怎么办？

答：先检查网络、API 地址、模型名、密钥和服务商额度。失败消息会显示“未送达，
点击重试”。如果对话已经继续，重试可能打断当前话题，请确认后再操作。

问：重新开始会话会删除以前的聊天吗？

答：通常不会。它会保留旧记录并建立新的剧情边界，后续默认只参考新篇章。群聊旧
记录会以浅灰色显示。解散群聊才是永久删除操作。

问：导出聊天记录后能不能恢复到软件？

答：不能。聊天记录导出是为了阅读和分享。需要恢复数据，请使用完整备份文件。

问：导入完整备份后为什么还要重新填写 API Key？

答：为了避免密钥跟随备份文件传播，完整备份不会保存账号密码和模型密钥。恢复后
需要在模型设置中重新填写。

问：导入备份后向量记忆为什么要重新建立？

答：备份保存的是原始记忆和资料，不保存与具体模型绑定的向量索引。恢复后重建索引
可以确保当前向量配置能够正确检索这些内容。

问：角色卡和完整备份有什么区别？

答：角色卡只分享角色设定，适合分享角色；完整备份用于迁移整个应用，包含聊天、
记忆、知识库和其他资料，但导入会替换当前数据。

十七、名词解释
============================================================

AI 模型：负责根据输入内容生成文字、理解图片或处理语音的服务。

API Key：访问模型服务的密钥。类似账号密码，应当保密。

上下文：AI 本轮回复时能够参考的全部内容，包括人设、记忆、知识库、历史聊天和
当前消息。

提示词：发送给 AI 的说明文字，用来规定角色身份、表达方式、任务和输出格式。

人设：角色的身份、性格、背景、目标、关系和说话方式。

记忆：从聊天和其他内容中整理出的经历、偏好、约定和事实。

向量记忆：把文字转换成便于比较含义的数字表示，用来按“意思相近”寻找旧记忆。
用户不需要直接操作这些数字。

Embedding：向量模型把一段文字转换成数字表示的过程。它不是聊天回复模型。

知识库：由用户主动提供的资料集合，例如世界观、设定、文档或背景资料。

索引：为了更快查找相关记忆或资料而建立的检索目录。修改内容后通常需要重建。

本地模式：在手机上完成检索处理，通常更注重隐私和无额外服务费用。

远程模式：把相关文字发送给第三方服务处理，可能更擅长理解语义，但需要注意隐私
和费用。

ASR：语音识别，把你的语音转换为文字。

TTS：文字转语音，把角色文字回复朗读出来。

Token：模型处理文字时使用的计量单位。上下文长度和输出长度通常以 Token 或字数
来限制。用户不需要手动计算，只要理解“可参考内容”和“可生成内容”存在上限即可。

提示词缓存：将多轮请求中不经常变化的规则和人设前缀重复利用，减少重复处理。是否
显示命中统计，取决于所使用的模型服务是否提供相关数据。
