# 1.14.16 可靠性修复与升级说明

## 本次修复
- 私聊重说不再预先覆盖原回复；成功提交使用内容比较保护，避免覆盖已撤回或修改的消息。
- 撤回/重说只使相关派生记忆及后代失效，记录归档而非删除；旧版无消息级来源的记录采用保守失效处理。短期摘要旧文本保存到设置中的修复备份键，再从有效历史重建。
- 记忆重建持久化进度，按批回放；滚动摘要扣除保留轮数再触发，超时进入失败状态，自动重试遵守开关与退避时间。
- 修复记忆提取失败后刚安排重试却又被标记跳过的问题；阈值大于30时不再永久无法触发提取。
- 知识库召回分页遍历当前模型签名的全部向量，而非只取最近候选；重建时保留旧可用索引，部分索引状态可继续使用。
- 动态评论持久化为任务，前台与后台共享数据库租约；评论写入和任务完成同事务，防止重复发布。最多4次尝试，详情页显示等待/失败及手动重试。
- 动态/评论输入框等数据库保存成功后再关闭清空；失败保留输入。公共动态/评论不注入私有记忆。
- 热路径部分全量消息读取改为单条查询及COUNT。

## 升级保护
- applicationId、签名配置不变，versionCode从62升至63。
- 未修改既有数据库表和索引定义，未添加迁移；新增查询复用原有reply_turns表。
- 不清空聊天、角色、动态、知识库或模型设置；不扫描旧动态补造互动任务。
- 不重置既有用户开关；后台执行时间受Android后台/网络限制，不保证即时。
- 撤回后的派生记忆重新提取会产生模型用量；遵守原有各来源的记忆生成开关。
