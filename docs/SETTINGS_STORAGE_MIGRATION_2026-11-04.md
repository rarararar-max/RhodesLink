# 1.14.29 设置存储切换修复（2026-11-04）

## 原因
旧版 diagnostic_use_plain_settings 仅切换读取库，不从加密库迁移资料和 API 配置。慢 Keystore 自动降级同样直接读取旧明文库。缺少当前有效库标记，反向切换有旧数据覆盖或新值不生效风险。原加密库未被切换代码删除。

## 修改
- SettingsStorageMigration 复制所有用户设置（String/Int/Long/Float/Boolean/StringSet），排除诊断控制键；commit 后读取校验，不记录配置值。
- UI 在 IO 线程预迁移和校验成功后保存切换请求。进程内保持原设置实例；重启时从原有效库重新同步，包含切换后、退出前的修改。
- 当前有效库通过 settings_storage_active_v2 标记。双向显式切换精确同步用户设置，包括空字符串和删除项。成功降级必须先完整复制并校验。
- 首次升级且旧版开关已开启时，从加密库补回明文库缺失或空字符串项，保留明文后来录入的非空值。由于旧版没有变更历史，无法辨别非空旧值与后来新值，采用保留明文非空值的保守策略。加密库不可读或已被清除时无法保证恢复，不自动删除源文件。
- 加密库不可读取时保留两库、记录错误类型并提示用户，旧明文视图不标记为恢复完成；迁移失败的显式切换尽量回到原有效库。
- 缓存实际设置对象，避免自检反复创建或重新选择设置库。诊断报告显示有效库与错误类型，不含 API Key 或个人资料。
- 诊断开关措辞改为结合日志判断，并说明明文存储缺少应用层加密。产品手册更新。
- 包含前一轮大记录备份分块读取与导入格式识别修复。
