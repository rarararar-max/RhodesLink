# 1.14.18 记忆、索引、动态与日记可靠性修复

## 修复与用户可见变化
- 记忆去重改为同来源、同会话、同隐私、有效期内的原子检查与插入；旧记录不做批量合并或重写。不同证据仍单独保存，检索保留现有去重显示。
- 记忆插入与返回ID同事务，避免并发写入取错数据库连接的last_insert_rowid。
- 编辑原记忆时，相关派生结论归档并删除其旧向量；不删除原记录。可能暂时减少旧结论引用，待后续有效证据生成。
- 记忆索引重建按条成功后替换，失败保留旧向量；重建、补建共享进程锁。向量模型变更不混用旧模型结果。
- 向量发布核对原记忆是否仍存在、有效且内容/隐私一致，向量与所属记忆的索引ID同事务提交。防止编辑/撤回/删除与后台索引交错后旧内容重新出现。
- 分层记忆按角色与来源串行生成，证据链接和父记录归档同事务。父证据已改动时，新结论归档；子结论索引未成功时保留父记忆用于召回。
- 记忆管理界面按实际索引记录、模型签名和有效期显示可用/待补建/模型变化状态，而非只检查ID。
- 清理私聊会话时，同时匹配旧来源ID和新epoch窗口来源ID；使用长度匹配避免会话ID中的下划线、百分号引起误删。
- 新日记与对应记忆生成意图同事务保存。日记成功立即返回，记忆独立处理失败可从队列恢复，不把已保存日记误报为失败。
- 日记超时正常结束回调，真正取消继续传播；同角色避免并发生成；新日记使用数据库自动分配版本号，保留原有版本。
- 日记昨日摘要按准确yyyyMMdd日期读取；群聊后续每日摘要也按同一日期键保存。旧版无日期键摘要不伪装成昨天事实，不修改旧摘要原文。
- 用户新发动态/评论与预定角色回复任务在同一事务提交；中断后启动恢复，不再等待记忆处理结束才创建回复任务。
- 来源队列区分L1生成完成与向量完成，缺失向量补建后刷新状态。知识库预计算查询向量传递原始模型签名，避免配置切换时混用。
- 客服说明同步本版行为。

## 覆盖升级保护
applicationId不变，versionCode65/versionName1.14.18；不修改既有表、索引定义或迁移脚本。新增SQL查询复用旧表。保留角色、聊天、日记版本、动态、知识库、客服记录、余额、密钥和各生成开关。没有升级时的历史数据清洗、旧动态补发、旧日记补生成或全量向量重建逻辑。现有已排队任务继续受原开关控制。

本版新增日记记忆队列只针对之后生成的日记；不会扫描全部旧日记补造任务。向量服务请求仍受用户原配置及原有缺失索引恢复逻辑控制。已有旧模型索引保留不代表能在新模型下使用，需要用户按现有入口重建。
