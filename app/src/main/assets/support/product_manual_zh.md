# 应用使用说明

## 快速开始 / 配置文本模型
路径：设置页面 > 模型设置。使用私聊、群聊、动态、日记、派遣和 AI 客服前，需要配置文本对话模型的厂商、模型名称、API Key；自定义厂商还需要接口地址。可使用连接测试检查配置。AI 客服使用当前已配置的文本模型，不需要单独配置客服模型。不要向任何人提供 API Key。

## 常见模型错误
HTTP 401 表示 API Key 无效、过期或填写错误。HTTP 403 表示 Key 没有权限。HTTP 404 表示模型名称或接口地址不存在。HTTP 429 表示限流、频率过高或额度不足。网络超时通常与网络、服务商或模型响应有关。上下文超限表示系统规则、历史、资料、当前输入和模型回复超过服务商实际容量。

## 聊天表现 / 历史回看
路径：设置页面 > 聊天表现 > 历史回看轮数。该数值决定每次请求最多尝试带入多少近期互动回合。数值越高，连续性通常更好，但请求可能更慢。历史回看不会修改已有聊天、短期摘要或长期记忆。

## 聊天表现 / 自动上下文
路径：设置页面 > 聊天表现 > 自动上下文。默认开启。开启后应用优先按历史回看轮数发送历史。若服务端明确返回上下文超限，应用会裁剪较早历史并自动重试，优先保留较近互动。调试日志的“特殊”分类出现“上下文超限自动裁剪”时，表示服务端拒绝过长请求后应用已重试。

## 聊天表现 / 手动上下文
关闭自动上下文后可设置上下文长度上限。手动模式适合已知上下文较小的中转服务，应用会在发送前裁剪较早历史。设置值不得超过当前模型或中转服务实际支持的总上下文长度。

## 为什么历史没有传给 AI
可能原因：历史回看轮数较低；会话曾重新开始；某条历史回复无法重新解析；服务端上下文超限后自动裁剪；手动上下文上限提前裁剪。排查路径：设置页面 > 调试日志，查看本轮发送内容的消息数，并在“特殊”分类查看“历史回复无法用于上下文”或“上下文超限自动裁剪”。

## 私聊 / 模式与状态卡
私聊有线上、线下和导演模式。线上模式只发送文字台词。线下模式可输出旁白和台词。导演模式中用户本轮明确描述的地点、时间、行动和事件结果优先作为场景事实。私聊状态卡包含状态、心情、位置、本轮简述和用户发言意图分析。意图分析是内部推断，不是用户确认的事实。

## 私聊 / 旁白与台词
线下和导演模式中，旁白是第三人称可见动作、位置、环境和即时变化；台词是角色实际说出口的话。旁白不得使用第一人称、角色台词或内心独白。用户明确写出的可见动作可以被旁白承接；愿望、邀约、假设和计划不等于已经发生的动作。回复重复时，可在设置页面 > 聊天表现中降低旁白或台词段数、最大字数，并提供更具体的新问题或新行动。

## 群聊 / 创建、成员与模式
群聊由已创建的干员组成。成员资料决定可发言角色和发言标识。线上群聊只输出成员文字消息；线下群聊可使用共享场景旁白；导演群聊优先使用用户明确建立的场景事实。名单外角色不能作为当前群成员发言。成员不说话时，请检查成员名单和禁言状态。

## 群聊 / 自动续聊
自动群聊需在对应群聊中启用。群聊空闲一段时间后，成员会根据最近主线继续聊天。等待时间和连续轮数可在设置页面 > 聊天表现 > 群聊中调整。自动群聊不触发时，检查群聊自动开关、空闲间隔、连续轮数和权限管理。

## 知识库 / 导入和索引
路径：设置页面 > 知识库。知识库用于给角色提供参考资料，支持从 TXT、Markdown 导入，也可直接在应用内编辑名称和正文。导入后应用会把资料自动切分为片段（分段）并建立索引。

要让知识库真正在对话中生效，需要同时满足：资料已导入并完成索引；在“此知识库适用场景”（私聊 / 群聊 / 动态 / 评论 / 日记）中关联到要用它的场景；在该知识库详情页“关联角色”中添加对应的干员。知识库只在关联角色且当前话题与资料相关时才会被用于生成内容。

知识库没有生效时，按此排查：索引是否完成（详情页可看到状态）；是否在适用场景中勾选；是否关联了正确的角色；是否切换过向量模型后旧索引未重建；以及问题本身是否和资料内容相关。

## 知识库管理
入口：设置页面 > 知识库 > 选择某个知识库进入详情页。

知识库详情页支持：编辑名称和正文、为它设置适用场景（私聊 / 群聊 / 动态 / 评论 / 日记）、关联角色、分段管理、开始或重建索引、以及永久删除。

- 分段管理：导入后自动按段落切分，可在分段列表查看、新增、删除、启用/停用某个分段；也可以在此编辑分段正文和关键词，调整检索覆盖。
- 开始 / 重建索引：资料变更或更换向量模型后需重新建立/重建索引。本地向量默认可用；使用“付费 Embedding（更好的记忆力）”则会向第三方服务发起真实请求并可能产生费用。
- 关联角色：为该知识库选择关联的干员，只有关联到的角色才会在后续生成中使用这份资料。
- 删除：永久删除知识库前请确认，删除后该资料无法恢复。

更多关于本地向量与第三方向量的区别，见“知识库 / 本地向量”和“知识库 / 第三方向量”章节。

## 知识库 / 本地向量
本地向量默认可用，不上传知识库文本或检索问题，不产生 embedding 服务费用，索引保存在本机。它适合明确关键词、产品说明和隐私优先资料；对同义词和模糊表达的检索通常弱于第三方向量模型。

## 知识库 / 第三方向量
第三方向量需要在模型设置中配置向量接口、模型和 API Key。它通常更擅长同义和模糊表达，但会将待索引文本与检索问题发送给用户配置的向量服务，且可能产生费用。切换向量模型后旧索引不兼容，需要重建。应用会在远程索引前请求确认。

## 动态、日记、派遣与权限
动态、评论、日记和派遣使用当前文本模型。自动内容的频率和免打扰时间在设置页面 > 每日自动内容中调整。权限管理用于控制干员主动消息、动态和群聊自动内容；关闭相应权限后自动功能不会继续产生内容。

## 语音、图片与备份
语音输入需要配置语音识别，语音朗读需要配置 TTS，图片聊天需要配置识图模型。无法识别图片时检查模型地址、模型名、API Key、网络和图片读取权限。聊天、角色、设置、记忆和知识库主要保存于本机；更换设备、清除数据或卸载前建议导出备份。恢复备份后仍应检查 API Key、文件路径和权限。

## 调试日志与反馈
路径：设置页面 > 调试日志。日志可查看模型请求、返回、最终保存内容、资料取用和失败原因。“特殊”分类用于历史回复无法用于上下文及上下文超限自动裁剪。反馈时建议提供应用版本、功能页面、复现步骤和不含 API Key 的错误摘要。联系方式位于设置页面 > 感谢名单与联系方式。

## 创建干员、开始私聊与编辑角色
路径：通讯录 > 新建干员。可填写名称、称号、性别、简介、头像、私聊人设和群聊人设。保存后，在通讯录点选干员即可进入私聊。

角色编辑中的“允许主动发私聊”决定该干员是否有资格参与每日主动私聊计划；关闭后不影响手动私聊。角色人设会影响说话风格和关注点。不要在人设中要求 AI 泄露 API Key、忽略应用规则或替用户做决定，这类内容不会改变应用保护规则。

## 如何让干员主动打招呼
需要同时满足：设置页面 > 每日自动内容中的“自动内容”和“主动私聊”均开启；该干员在设置页面 > 权限管理中允许主动私聊；干员已有可用私聊上下文；未处于用户发言后的静默时间和免打扰时段。

“角色每日主动概率”控制每个有资格干员当天被选中的概率；“每天最多主动角色数”限制当天最多有多少角色主动联系；“用户发言后静默分钟”避免刚聊完就再次主动消息。每个符合条件的角色每天最多主动一次。想让特定角色主动，应为该角色打开主动私聊权限，并保持总开关、概率和每日上限足够高。

## 提示词模板编辑
路径：设置页面 > 聊天表现 > 编辑角色说话规则。私聊和群聊分别有不同模式与模块：角色规则、固定行为、输出协议和运行时资料。

角色规则用于人设、语气和互动偏好；固定行为用于场景连续性、内容决策和群聊主线；输出协议用于标签、段数和字数；运行时资料用于调整资料顺序和占位符。模板不是完整请求，应用仍会动态加入历史消息、用户本轮输入、实时资料和应用保护规则。

修改建议：先复制默认内容再小幅调整；保留必要占位符和输出标签；一次只改一个模块并实际测试；出现回复格式异常、台词拆分异常或历史连续性变差时可使用“恢复默认”。未知占位符会原样发送给 AI，可能降低回答质量。自定义提示词不能让应用跳过 API Key 保护、隐私保护或“不得替用户确认未明确决定”等规则。

## 如何创建群聊、添加成员和禁言
路径：通讯录 > 新建群聊。填写群名称后，在群成员区域点击添加按钮选择已经创建的干员。群聊可设置头像、群规，并可分别为成员关闭“允许发言”；被禁言成员保留在群内但不会在本轮发言。

创建后可进入群聊编辑页增加或移除成员。至少保留一个允许发言的成员，否则群聊无法生成角色回复。群规是额外的群聊约定，适合填写所有成员共同遵守的简短规则，不应替代每个角色的人设。

## 记忆设置、记忆生成与注入开关
路径：设置页面 > 记忆。记忆生成和记忆注入是分开的：关闭生成不会删除已有记忆；关闭注入只会阻止对应场景读取该来源。

“统一记忆系统”控制记忆的生成、索引和召回。私聊记忆、群聊记忆、动态记忆、评论记忆和日记记忆分别控制不同来源是否生成可检索记忆。滚动摘要用于概括近期对话；每日摘要用于回顾一天内容；长期沉淀允许近期记忆合并为更稳定的长期印象。

“注入”页决定私聊、群聊、动态、评论和日记可读取哪些来源。关闭某来源不会删除它，只是不再在对应场景使用。重新开始私聊或群聊后，新回复会过滤旧会话的历史、摘要和向量记忆。

## 每日自动内容与权限管理
路径：设置页面 > 每日自动内容。“自动内容”是总开关，关闭后不再生成计划动态或主动私聊，但手动聊天和手动催发动态不受影响。“每日固定动态”控制有动态权限角色是否按计划发布动态；“每角色每日动态数”控制每天数量。

主动私聊开关、每日概率、每日最多主动角色数、用户发言后静默分钟和免打扰时段共同决定主动打招呼。免打扰只影响主动私聊，动态照常。设置保存后应用会重新安排当天计划；系统省电策略可能让后台内容实际到达时间略晚。

路径：设置页面 > 权限管理。干员页可批量控制每名干员是否允许主动私聊、是否允许参与自动动态。群聊页可单独开启或关闭每个群的空闲自动聊天。关闭权限不会删除已有聊天和内容，只会阻止之后的自动生成。

## 送礼、龙门币与项目打赏
在私聊或群聊中可使用送礼功能。送礼需要选择或裁剪礼物图片、填写 1 到 10 个字符的礼物名称、选择收礼角色，并消耗龙门币。群聊可同时选择多个成员，费用会按收礼人数计算。余额不足、未配置文本模型或礼物图片未保存时无法送出。

龙门币主要用于应用内互动和送礼，不等同于真实货币或充值余额。项目支持与联系方式位于设置页面 > 感谢名单与联系方式；该页面按平台展示公开感谢名单、收款二维码和联系方式。向项目打赏是自愿支持，不会自动解锁角色、模型额度或应用内特权。

## 外观、数据管理与会话主页
路径：设置页面 > 外观设置，可切换白天、黑夜和罗德岛终端外观，选择后立即保存。

路径：设置页面 > 数据管理，可设置聊天记录、记忆锚点、日记、动态和派遣历史的保留期限，并可立即清理过期数据。清理不可恢复，建议先导出备份。

聊天主页的“从主页移除”只隐藏会话，不删除数据；收到新消息后会话会再次出现。私聊或群聊的“重新开始”会保留旧记录供查看，但后续生成默认只参考新会话内容。

## 聊天表现 / 修改记忆长度、历史长度和数据保留时间
“历史回看轮数”控制每次请求带给 AI 的近期聊天回合数量；它不是记忆保存天数。“设置页面 > 记忆”中的摘要阈值和记忆提取阈值控制多久生成一次摘要或记忆；“设置页面 > 数据管理”中的聊天记录、记忆锚点、日记、动态和派遣历史保留期限控制本机数据多久后自动清理。想让 AI 在单次聊天里看到更多原始内容，改历史回看轮数；想让记忆更频繁生成，改记忆生成阈值；想让本机保留更久，改数据管理中的保留期限。

## 导出人设、角色卡和完整备份
路径：设置页面 > 数据管理 > 角色设定分享 > 导出角色设定。先选择角色，再选择保存位置，会导出包含角色人设和头像的角色设定卡；角色卡不包含聊天、记忆、日记和动态。

如果要迁移整个应用，使用设置页面 > 数据管理 > 备份与恢复 > 完整备份。完整备份可以包含角色、聊天、记忆、日记、动态和非敏感设置，但不会保存 API Key 或模型密钥；换设备后需要重新配置模型服务。仅想分享聊天内容时，使用“保存聊天记录”，它是可阅读文件，不能用于恢复应用数据。

## 个人资料、头像和用户身份设定
路径：设置页面 > 身份设置。昵称不能为空；性别和身份介绍可选。可从内置颜色头像中选择，也可选择图片后裁剪为方形头像，图片会复制到应用本机存储。昵称、性别、介绍会作为用户资料参与角色聊天，修改后不会改写历史聊天中的旧称呼。

保存前可放弃修改。头像无法显示时，可重新选择图片或切换为内置颜色头像。用户身份介绍适合写稳定的角色背景、称呼偏好和身份设定；不要在这里填写 API Key、密码或要求模型忽略应用规则的文字。

## 更换聊天背景和群头像
私聊或群聊详情页的菜单可更换背景图，也可恢复默认背景。背景图仅改变当前会话视觉外观，不影响角色人设、记忆、模型回复或聊天历史。群聊编辑页可设置或更换群头像；群头像只用于群聊列表和群聊界面显示。

背景图片无法保存或显示时，检查图片读取权限和本机存储空间；可先移除当前背景，再重新选择图片。

## 角色编辑的全部字段和关系
路径：通讯录 > 干员 > 编辑。除名称、称号、性别、简介、头像、私聊人设和群聊人设外，还可设置当前状态、心情、地点、用户关系说明、主动私聊权限、动态参与权限、语音音色与播放音量、知识库关联和角色关系。

私聊和群聊人设可以分别保存多个槽位，用于不同风格版本；切换槽位不会删除旧内容。AI 人设助手可根据角色需求生成标题、简介和人设草稿，必须手动确认后才会写入编辑内容。

角色关系是单向的：编辑角色 A 时添加 A 到 B 的关系，表示 A 如何看待 B；希望 B 也有对应看法，需要再编辑 B 添加反向关系。关系会影响群聊、日记和部分关系背景，不会自动替代角色人设。

## 删除角色和批量删除
路径：设置页面 > 权限管理 > 干员。可批量选择角色后保存并确认删除。删除角色会永久删除该角色的私聊、记忆、关系、动态和相关数据，也会取消该角色计划中的自动内容。删除无法恢复，建议先使用完整备份或导出角色设定卡。

仅想停止角色主动私聊或自动动态时，不要删除角色；关闭对应权限即可。手动私聊仍可继续使用，除非角色本身被删除。

## 聊天表现全部参数
路径：设置页面 > 聊天表现。

私聊页的台词最少/最多段数和最少/最多字数，控制每轮角色台词数量和长度。线下/导演模式的旁白最少/最多段数和字数，控制动作、环境和场景描述的数量与长度。段数或字数过高会让单轮更长、更慢、更耗 token，也更容易出现重复；最小值不能高于最大值，应用会自动保持有效范围。

群聊页可设置每条成员消息的最小/最大字数、每轮每位成员最少/最多发言次数、线下群聊旁白数量和长度，以及空闲自动群聊的最小/最大等待秒数和自动连续轮数。成员越多、发言次数越高，回复越长且等待越久。

“创意程度”是模型 temperature。数值低时回复更稳定但可能重复；数值高时更有变化但更可能跑题。它不会改变角色资料、历史或模型本身的最大能力。

## 故事设置：动态、日记和派遣文本
路径：设置页面 > 动态、日记与派遣。这里控制动态文本长度、参考最近动态数量、和用户相关动态的倾向、评论上下文/记忆数量、围观角色数量、评论长度、日记长度和派遣叙事长度。

这些设置只影响 AI 生成的文本密度、参考范围和风格，不会改变派遣真实持续时间、派遣奖励结算、手动日记是否保存或自动内容总开关。数值过高会增加模型输出、等待和 token 消耗。

## 动态：发布、提及、评论和开关
动态页可手动发布文字动态、提及多个角色、点赞或取消点赞、评论和回复评论。动态列表会加载较早内容，并在页面打开时检查未读新动态。手动“催发”动态会立即请求生成，不受“每日自动内容”总开关影响。

想关闭自动动态：进入设置页面 > 每日自动内容，关闭“每日固定动态”或关闭“自动内容”总开关；也可进入设置页面 > 权限管理，为单独角色关闭“动态权限”。关闭后不会删除已经发布的动态。

## 语音聊天：前置配置和使用方法
语音通话前需要三类服务均可用：文本对话模型、语音识别 ASR、语音合成 TTS。路径：设置页面 > 模型设置。ASR/TTS 可使用各自 API Key；部分配置会回退使用文本模型 API Key。首次录音时 Android 会请求麦克风权限。

进入角色私聊后使用语音通话入口。按住说话模式会在松开后发送识别结果；连续模式会自动检测约 1.2 秒静音后发送，最长约 120 秒会强制提交。识别文本会进入当前私聊上下文，角色回复会作为语音交流保存。结束通话会在聊天中写入时长记录。

语音不可用时依次检查：文本模型是否可用、ASR 和 TTS 接口/模型/API Key、麦克风权限、网络、角色 Voice ID 和音量。某些 TTS 服务没有默认音色，必须在角色编辑页为角色填写 Voice ID。

## 陪睡模式和闹钟
陪睡是横屏全屏的语音互动功能，需要可用的文本模型、语音识别和语音合成。自动陪睡会持续监听；达到设定无操作时间后进入休息状态、关闭麦克风并逐渐变暗，点击屏幕可唤醒。

陪睡中的闹钟仅在陪睡页面保持打开时有效。叫醒文案可选择 AI 自动生成或固定文案，可进行稍后提醒。退出陪睡页面后，不应把它当作系统级后台闹钟使用。

## 记忆系统：开启、生成、注入和维护
路径：设置页面 > 记忆。

“统一记忆系统”是总开关，控制 Memory V2 的生成、索引和召回。关闭后已有记忆保留但不参与对话。私聊、群聊、动态、评论和日记记忆开关分别控制各来源是否提取；滚动摘要总结近期内容；每日摘要记录每日回顾；长期沉淀控制 L1 近期记忆是否继续合并为 L2/L3 长期信息。

“摘要游标”只处理上次提取后新增消息。私聊/群聊记忆提取阈值决定新增多少消息后请求模型提取一次。群聊记忆复制给成员只复制高重要度的承诺、提醒、偏好、观点和自我认知，不复制普通事件和瞬时情绪。

“注入”页决定每个场景能读取哪些来源。生成开关和注入开关互不等同：关闭生成不删除旧记忆；关闭注入不删除旧记忆，只是不把它们发送给对应场景。快速/平衡/深度检索策略调整候选池与检索工作量，不会凭空增加角色已知事实。

更换向量服务、向量模型或向量地址后，旧向量索引与新签名不兼容，应按提示重建索引。记忆管理页可查看有效、已索引、待补建和失效数量，并仅补建待索引内容。使用付费 embedding 重建可能按每条记忆产生请求费用。

## 自动群聊：开启条件、间隔和停止条件
自动群聊需要同时满足：设置页面 > 每日自动内容的“自动内容”总开关开启；设置页面 > 权限管理或群聊编辑页中该群的“空闲自动聊天”开启；群内至少有可发言成员；网络可用。

每轮自动回复后，应用会在你设置的最小和最大间隔之间随机选择下一次等待时间。自动连续轮数达到上限后会停止，直到用户继续发言或刷新相关设置。自动群聊会通过后台任务安排，系统省电、网络限制或应用被强制停止时可能延迟。

## 派遣：组队、时长、预算和奖励
派遣开始前需要：配置可用文本模型；选择恰好 5 名未在派遣中的干员；选择任务类型；选择 1、3 或 5 小时持续时间；投入不少于 100 且不超过当前余额的龙门币。最多可同时进行两支派遣队。

预算会先扣除。更高预算通常提高准备和奖励上限，但不保证盈利；中断或失败不一定返还投入。派遣过程和结局由文本模型生成，故事设置只影响叙事长度和快慢，不保证任务结果。完成后在派遣历史中查看记录和结算。

## 龙门币：获取、消耗和限制
龙门币余额不会低于 0。私聊和群聊的有效手动互动可按每日规则奖励龙门币；送礼和派遣会消耗；麻将、斗地主和跑得快结算也可能改变余额。不同玩法的奖励和扣除取决于结算结果，不应把龙门币视为真实货币、充值余额或模型服务额度。

## 游戏室：麻将、斗地主和跑得快
入口：功能页 > 游戏室。游戏室提供三款与干员对战的牌局：简化麻将、斗地主、跑得快。开始游戏前先完成两个前置：选择参与的对战干员；确认这些角色没有处于不允许参加的状态。牌局规则与 AI 出牌由本地规则引擎处理，配置文本模型后可生成过程或结算对话，但模型不决定牌局合法性。

麻将（四人对局）
- 玩法：简化日式/四人麻将，需要为当前玩家选择 3 名干员作为对手（也可随机组桌）。手牌规则为“四组牌加一对将”，支持胡、碰、吃、杠；结算时按役种和番数计点（如立直、荣和、自摸、放铳），也有流局。
- 模式：快速一局、四局积分、八局积分；可“继续上次牌局”，可查看对局历史。
- 助手：对局中有 AI 助手提示，帮助理解可出牌与得失。
- 结算：每局显示暂计，最终局后按净收益计入/扣除龙门币。

斗地主（三人对局）
- 需要选择 2 名干员；地主拿 3 张底牌，另两人为农民。
- 牌型支持三带、顺子、连对、炸弹和王炸；炸弹和“春天”（一方未让其出牌就打完）会翻倍，还有反春天等倍率。
- 基础分与当前倍率决定结算输赢，赢家结算联动龙门币。

跑得快（三人对局）
- 需要选择 2 名干员；支持三带、顺子、连对、炸弹，先出完牌的玩家获胜。
- 按胜负结算龙门币；对局中 AI 会自动选择牌组，可查看出牌规则帮助。

注意：未完成的扑克对局不会保存，中途退出该局结果不结算；龙门币余额变动见“龙门币：获取、消耗和限制”章节。

## 备份、角色卡导入和恢复模式
完整备份用于换机或恢复，导入会替换当前角色、聊天、记忆、日记和动态；导入前应用会自动创建恢复前备份并保留最近几份。外部图片可能无法迁移，API Key 和模型密钥不会恢复。

导入角色设定卡时可选择：新建副本；覆盖现有角色；仅更新人设和头像。覆盖会更新角色资料、关系、状态等，但保留聊天和共享经历；仅更新人设和头像不会改动聊天、记忆、关系或角色数值。关系只有在接收方已存在对应角色时才能导入。

## 调试日志：开关、完整内容和隐私
设置页面 > 调试日志可按私聊、群聊、记忆、动态、特殊等分类查看，并可筛选成功/失败。日志最多保留一定数量条目，可复制单组或全部并清空。

开启“记录完整模型输入与输出”会在本机日志中保存完整提示词、历史和模型原文，便于排查，但可能包含私密聊天内容。反馈前请确认不含 API Key、密码或不希望分享的对话；普通调试关闭后，关键失败诊断仍可能保留。

## 手动新增记忆
路径：通讯录 > 干员 > 进入该角色的私聊记忆页（如需批量请看设置页面 > 记忆 > 打开记忆管理）。

手动新增记忆前，需要先开启“统一记忆系统”（设置页面 > 记忆 > 总开关），否则“新增”按钮不可用。进入某角色的记忆页后点击“新增”，填写记忆内容和“重要性 0-100”（默认 80），保存后即成为该路径下的手动记忆。

手动记忆与自动提取的记忆不同：它不来自任何一次会话，由你直接写入。这条记忆由当前角色拥有，可在私聊、动态、评论和日记中按对应“注入”页的手动记忆开关引用；当前不会注入群聊，其他角色不会直接获得。新增后会自动建立检索索引，删除某条记忆会同步清除其索引，角色之后不会再引用这条内容。

可在记忆页按来源、记忆等级（L1 近期记录 / L2 长期记忆 / L3 角色记得的你）、权限（私密 / 可传开 / 公开）和排序筛选。来源为“手动添加”的即为手动新增的记忆。

## 关系网与亲密度
路径：角色编辑 > 关系网编辑，或在干员详情页查看关系网。

关系用于描述干员之间的熟悉和信任程度。不同干员之间可设置的关系类型包括：恋人、挚友、朋友、战友、队友、对手、情敌、暗恋对象、家人、哥哥/弟弟、姐姐/妹妹、母亲、父亲、儿子、女儿、监护人、上司、下属、队长、队员、导师、学生等。每种关系可用 0-100 的亲密度表示亲近程度：0-19 基本不知道对方，20-39 只会知道一件很重要的事，40-59 会知道部分重要计划/偏好/经历，60-79 会知道较多近期近况，80+非常亲近，能自然了解更多互动经历。关系默认单向。

“同时创建/更新互补关系”开关默认关闭。打开后，保存时会为对向干员自动建立/更新对称关系（例如 A→B 设为“姐姐”并开启互补，会同时为 B→A 生成“妹妹”）。不开启时，A 把 B 当恋人不代表 B 也把 A 当恋人。

关系主要影响群聊中的称呼与互动、日记素材，以及“公开记忆”能否通过关系传递。注意：只传递公开记忆，私聊中的私密内容不会直接外传；关系网近况只在私聊中使用，不会同步到群聊或公开内容。

## 互动印象
入口：功能页 > 大家的印象。

印象是干员在与你的互动中逐渐形成的对你的了解，按稳定程度分为三层：互动印象（L1，偏好、情绪和身体状态按记录日期保留）、持续了解（L2，经多次互动合并出的偏好、约定和关心点）、长期印象（L3，反复互动后形成的稳定了解）。多聊几次后，干员会逐渐形成对你的近期了解和长期印象。

每条印象带有类型标签，例如：偏好、情绪、身体状态、约定、关心提醒、意图愿望、评价观点、自我认知。可在详情看到由哪位干员、发生于或记录于什么时间。支持单条编辑、单条删除，以及“清空所有印象”（清空不会删除聊天记录、动态或评论）。

## 剧情存档
入口：进入某干员私聊后，点击右上角菜单 > 剧情存档。

剧情存档用于保存和恢复聊天剧情进度，适合在长剧情中做关键节点的存档。点击“保存当前进度”可填写存档名称和“续写备注”（可选，例如“保留约好看日出的设定”），保存后由文本模型整理生成剧情简介。整理完成后可“读取”，将恢复为保存时的聊天模式（线上 / 线下 / 导演）和最近 5 个完整回合；当前聊天后续会保留在聊天记录中仅供回看，不再影响当前剧情。

存档数量随与该角色好感度（亲密度）提升而解锁：初始 3 个，0-199 为 3 个、200-399 为 5 个、400-599 为 8 个、600-799 为 12 个、800-999 为 16 个、达到 1000 为 20 个，最多 20 个。删除某个存档只会删除这个存档，不影响当前聊天或其他存档。整理剧情存档需要可用的聊天文本模型。

## Token 消费统计
入口：功能页 > 消费统计。

这里记录应用调用文本模型的 Token 消耗。可按“今日 / 本周 / 全部”切换查看总量，也可按分类查看：私聊、群聊、记忆、动态、日记、其他（派遣 / 麻将 / 扑克等）。每个分类都区分“输入”和“输出”Token 并显示合计。全部和本周视图还会展示“每周消费趋势”折线图和“分类消耗”柱状图。

页面底部提供“重置统计数据”，清空所有类别的累计与今日数据，此操作不可撤销。统计数据仅用于本地查看消耗，不涉及余额。

## AI 客服
入口：设置页面 > AI 客服（右上角“AI客服”入口）。

AI 客服使用你当前已配置的文本对话模型回答产品使用问题，不需要单独配置客服模型。它依据应用内置的使用说明（产品说明资料）和知识库检索来回答，回答末尾会标注“参考”的实际章节。若资料里没有明确答案，它会提示“当前产品说明未覆盖这个问题”。

使用前请先在设置页面 > 模型设置配置好文本对话模型并确认可用。开启“第三方向量模型”后，客服可用向量检索匹配同义问题；未确认时会继续使用本地章节检索，不影响使用。

## 外观皮肤
路径：设置页面 > 外观设置。

除白天/黑夜切换外，界面还有可选的整套皮肤，用于直接切换白天/黑夜与界面外观：
- 经典白昼 / 经典黑夜：保留标准明亮或柔和的低刺激界面。
- 罗德岛终端·昼：冷灰档案底色，橙色行动标记与工业结构线（RHODES TERMINAL / DAY）。
- 罗德岛终端·夜：深蓝灰终端面板，适合沉浸式夜间使用（RHODES TERMINAL / NIGHT）。
选择后立即保存，切换到罗德岛终端皮肤时会切换对应外观风格。

## 模型设置：五类服务与各自用途
路径：设置页面 > 模型设置。

模型设置里配置五类服务，除聊天模型外都可在各自区块单独填写 API Key（留空则复用聊天模型 API Key），并各有独立的“测试”按钮可验证是否可用：

- 聊天模型（文字对话）：私聊、群聊、动态、日记、派遣和 AI 客服等所有生成文字的功能都需要它，是必配项。
- 语音识别 ASR（文字转文字）：语音通话、陪睡、语音输入的“按住说话/连续模式”需要它，把你说的话转成文字。地址通常以 ws:// 或 wss:// 开头，也提供小米、阿里千问等预设。
- 文字转语音 TTS（文字转语音）：语音通话、陪睡和角色朗读需要它，把角色文字回复合成语音播报。部分服务没有默认音色，需在角色编辑页为角色填写音色 ID。
- 识图模型（视觉）：聊天中向角色发送图片时需要它，识别图片内容供角色回应。可使用阿里千问视觉接口或硅基流动等支持 Qwen3-VL 的服务。
- 向量模型 / 记忆增强（Embedding）：用于知识库和记忆的语义检索。未配置时使用本地向量；配置付费 Embedding 可获得更好的同义与模糊匹配，但可能产生费用。

配置顺序建议：先配好聊天模型，需要用到语音再配 ASR 和 TTS，需要发图再配识图模型，希望更好记忆检索再配向量模型。任意服务失效时，先看它对应的区块有没有配齐地址、模型名和 API Key，再用测试按钮定位问题。

## 语音朗读与角色音色
语音通话、陪睡和角色朗读（TTS）播出的声音由“语音音色”决定。广播在发送语音前，需要在角色编辑页为每个要出声的角色填写音色 ID（语音音色一栏）；不填写时会使用当前 TTS 服务商提供的默认音色。

- 填写位置：通讯录 > 干员 > 编辑 > 语音音色。
- 音色 ID 取值取决于你用的 TTS 服务商，例如某些服务使用类似 male-qn-qingse 的拼音音色，Vocu 则需填写其提供的 Voice ID（UUID）；Vocu 接口不需要填写模型名。
- 填写后可点“测试音色”试听并确认能否正常播放。
- 语音通话、陪睡和 TTS 会优先使用这里填写的音色 ID；如果某一角色没有声音，先检查该角色是否填了有效的音色 ID，以及 TTS 是否配置并可测试通过。

## 向角色发送图片（识图）
私聊和群聊里可以给角色发送图片，角色会基于图片内容自然回应。发送图片前，需要先在设置页面 > 模型设置配置好识图模型（识图地址、模型名，密钥留空则复用聊天密钥），未配置时应用会提示“图片聊天需要先设置识图模型”。

- 图片需为可读取的 JPG/PNG；无法选择或加载时请重试其他图片。
- 发送后若识别失败、角色没有识别到内容，可重试发送。图片识别依赖识图模型的地址、模型名、API Key、网络和图片读取权限。
- 需要自然地用角色身份回应图片时，会在本地构建“用户发送图片”的上下文交给识图模型后由聊天模型承接，不要苛求识图工具式的机械描述。
- 建议：首次配置后在模型设置点“测试识图模型”确认可用，再进入聊天发图。

## Galgame 互动剧情
入口：功能页 > Galgame。

Galgame 是本应用内置的互动剧情（视觉小说）创作与游玩工具，可用于创建、导入和游玩你自己的互动剧情，产出类似独立 AVG 的体验。

- 创作：按引导依次创建游戏剧情、角色、场景、章节，可录入事件、道具和变量，上传透明 PNG 立绘与场景背景图，并做统一立绘适配（含 9:16 试玩裁剪预览）。支持 AI Galgame —— 借助文本模型辅助生成/推进剧情。
- 游玩与存档：可进入试玩模式游玩章节，支持多个存档槽位保存/读取进度，也支持继续未完成的草稿。
- 导入与导出：可导入 .rdg 剧情包；可导出 H5 游玩版（.html）分享或本地游玩，适配移动版与电脑版。
- 删除：删除游戏/场景/资源前请确认，删除操作不可恢复。

剧情相关的“剧情存档”见“剧情存档”章节；Galgame 与普通私聊剧情的存档机制相互独立。

## 聊天道具商店
进入：在某个干员的私聊输入框上方点“🎒 道具”。

道具商店用龙门币购买聊天道具，每件道具固定价格（当前为 100 龙门币，余额不足时无法购买）。使用道具会消耗龙门币，可提升聊天玩法的多样性。

- 催眠怀表：购买后输入催眠指令，对当前干员施加强制指令，持续 10 轮对话，期间输入框会显示催眠剩余轮数；可随时“中断催眠”提前结束。购买下一轮前可重新设定指令。
- 看穿眼镜：购买后读取当前干员的内心独白（第一人称心理活动）。内容只在该界面/弹窗展示，不写入聊天记录；读取失败会退回本次费用。

龙门币获取与用途见“龙门币：获取、消耗和限制”章节。

## 聊天记录查看与搜索
入口：私聊界面右上角菜单 > 聊天记录；群聊界面同样有“聊天记录”入口。

可查看当前干员/群聊的聊天记录，支持按关键字搜索。结果区分“历史聊天”与“当前聊天”，命中后点击可“跳转到这条聊天”。记录里的图片、AI 回复都会以可读形式展示（如 [图片]、[AI回复]）。

聊天记录仅供回看，不会影响当前剧情或后续生成；删除聊天、重新开始会话会改变可查看的记录范围。此处的“历史回看”不是“聊天表现”里的历史回看轮数（那控制每次请求带给 AI 的历史量）。群聊记录还可查看每条消息的发送者与旁白。

## 聊天排行榜
入口：功能页 > 聊天排行榜。

统计各干员的聊天数据并按好感度、消息数排名，分为“昨日排行”与“历史总榜”两个榜单，前三名显示奖牌。用于查看你和各干员的互动热度。排行榜数据来源于本地聊天记录统计，只用于查看，不影响游戏玩法或余额。

## 礼物墙与收到的礼物
干员详情页会展示“礼物墙”——该干员收到过的礼物列表。可在详情页清空礼物墙（清除后无法恢复，需确认）。送礼并收取礼物见“送礼、龙门币与项目打赏”章节。

## 互动消息与未读
入口：动态广场（功能页 > 动态广场）顶部“互动消息”。

用于集中查看与你的动态、评论相关的互动消息（他人回复、提及等），支持一键“全部已读”，顶部按钮会显示未读数。此页面只汇总互动类消息，不影响你已发布的动态内容。

## 会话主页管理：置顶与已读
路径：聊天主页（会话列表）。

在聊天主页的每个会话上，可对单个会话做以下操作：
- 置顶 / 取消置顶：把常用会话固定在列表上方，方便快速进入。
- 标记已读：将该会话的未读消息标为已读；右上角菜单还有“全部标记已读”，一次清空所有会话的未读数。
- 从主页移除：只会让该会话暂时不在主页显示，不删除数据；收到新的消息后会自动重新出现在主页。
- 移除主页所有会话：批量隐藏全部会话，任一会话收到新消息后会重新出现。
未读会话会在列表上显示未读条数角标，便于查看还有哪些没看。

## 解散群聊
路径：进入群聊编辑页（群聊详情 > 编辑群聊）> 解散该群。

解散群聊会将群聊及其聊天记录永久删除，且无法恢复。解散前请确认不再需要这份群记录；如需保留，可先导出或备份。解散后，该群成员里对应的干员仍是独立角色，不影响它们在其他群聊或私聊中的使用。

## 感谢名单与联系方式
路径：设置页面 > 感谢名单与联系方式（设置页向下滚动到底部）。

该页面用于展示项目作者与贡献者、公开赞助名单，以及项目的打赏与联系方式，包括：
- 如何加群、如何联系作者、如何打赏捐款：都可在本页找到对应的二维码和联系方式。
- 贡献者名单：策划/AI 架构/基础开发、开发/代码架构重构、美术等署名（点击名字可跳转到对应的个人主页）。
- 版本与版权信息：当前版本号和版权年份。
- 赞助名单：页面提供“赞助与联系方式”“微信”“哔哩哔哩”“支付宝”“爱发电”“QQ”等标签页。其中“赞助与联系方式”页展示打赏/捐款收款二维码、加群二维码和联系方式二维码；其他标签页按金额从高到低展示各平台的公开赞助名单，并标注数据统计时间段。

说明与注意：
- 向项目打赏、捐款或捐赠是自愿支持，不会解锁角色、模型额度或应用内任何特权，也不会影响功能使用。
- 如需加群、反馈问题或联系作者，可在该页面的二维码和联系方式中查看；应用官方不会通过该页面之外的渠道主动索要你的 API Key、密码或账号信息，如收到自称官方的索取请求，请勿提供。
- 若无法打开页面中的链接或二维码失效，可通过页面展示的联系方式或社区渠道反馈问题。
